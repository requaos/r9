# How r9 Works

**Please update with any material code change!**

This document summarises the flow of each implementation as it currently stands.  We do this because r9 is a hobby project that is dipped in and out of, with months between dips.  In that context, it's really hard to remember how it works and why.  A document like this also serves as a useful introduction to the project.

## aarch64

The crate is a platform tree: `src/platform/{mod.rs,virt/,raspi3b/,raspi4b/}`, dispatched on `--cfg platform="<name>"`, which xtask emits from the `[config] platform` key of the selected `aarch64/lib/config_<name>.toml`.  The raspi modules keep the miniuart/mailbox/GPIO drivers; `platform/virt/` carries the qemu `-M virt,gic-version=2` target (PL011 console, GICv2, generic timer).

### Boot contract (qemu virt)

Virt boots the cargo-built **ELF** directly as `-kernel` (no objcopy/gzip flat-image step; `[dist] format = "elf"`), plus `-dtb aarch64/lib/virt-gicv2.dtb`.  On qemu 11.1.2 an ELF `-kernel` boot enters directly at EL1 and passes **x0 = 0** — no DTB pointer — so both DTB consumers substitute the fixed physical address `0x40000000` (where qemu loads the `-dtb` blob): `init_vm` pre-MMU (raw PA, with a putstr marker) and `main9` on the VA side.  Raspi still receives the DTB pointer in x0 from its boot stub.

The DTB is a committed pair: `aarch64/lib/virt-gicv2.dts` (reviewable source, regeneration procedure in its header) and `virt-gicv2.dtb` (the blob).  Regenerate on qemu pin bumps: `qemu-system-aarch64 -M virt,gic-version=2 -cpu cortex-a72 -machine dumpdtb=<out>` — the `-cpu cortex-a72` is load-bearing, the default-cpu dump lacks `arm,armv8-timer` and the SMC64 psci IDs — then round-trip through `dtc` (dtb→dts→dtb) and commit both.  Qemu injects `/memory` and `/chosen` at `-dtb` load time, so the committed blob stays minimal.

### Early initialisation (Assembly)

Execution begins in `l.S` at the `start` label.  The entry runs on raspi (stub-loaded) and on qemu virt (ELF entry, directly at EL1) alike.

The code in `l.S` exists to bring us to a state where we can run kernel code in the OS level (EL1).  In order to get there, we run through a number of steps:
1. Disable other cores
2. Ensure we're in EL1
3. Set up an early debug UART for printf-style debugging — cfg-selected per platform: the raspi miniuart body is unchanged; virt writes the PL011 at PA `0x09000000` with zero init (qemu pre-configures it).  Once initialisation has completed we output a single '.' so we at least know we've gotten that far.
4. Set up a set of initial page tables and enable the MMU.  Tables are configured to identity map and to map in kernel space, with a recursive page table entry.  The identity map ensures the code in l.S can continue to run once the MMU is enabled, and allows it to then jump into the higher half of the address space.  The identity window is per-platform: raspi maps PA 0–2MiB (kernel at `0x80000`); virt adds a second 1GiB block at PA `0x40000000` covering the kernel (`0x40080000`) and the DTB.  Note that qemu's ELF entry skips the EL2 path below, so enables l.S performs there (e.g. `CPACR_EL1.FPEN`) are re-done Rust-side on virt (`init_vm`).
5. Set up the initial stack (size set by STACKSZ - 4KiB), defined to be in BSS at the bottom of the file.
6. Clear the BSS.
7. Jump into the rust code, entrypoint `main.rs::main9`.

### Initialisation (Rust)

We're now in rust, in `main9`, and at a highlevel we:
1. Set up interrupt handlers early (`trap::init` installs the EL1 vector table) so that we get a bit of feedback if things go wrong.  IRQ unmask is deliberately split out (`trap::unmask_irq`) — see the ordering rule below.
2. Parse the device tree, enabling more informed initialisation.
3. Set up the mailbox (rpi-specific, but allows us to extract more information from the hardware, and interact directly in certain ways).
4. Initialise the [console](#devcons), ensuring we can use `port::println` to write to the UART.  On virt this is a `Pl011Uart` discovered from the DTB (`arm,pl011` → translated reg block → MMIO map), polled-TX, no GPIO/mailbox setup.
5. Write out some useful system information.  On virt the "what machine am I on" slot is DTB-derived (memory range from `/memory`, `found:` lines for `arm,pl011` / `arm,cortex-a15-gic` / `arm,armv8-timer`) instead of the mailbox board dump.  Right after the banner, an initrd configured via TOML data gets its probe marker (`initrd: start=… end=… size=…`, parsed from `/chosen` `linux,initrd-start/end`, validated against the `/memory` node, reserved in pagealloc) and a paqfs proof: the image range is mapped into the kernel table at KZERO+PA (the same `VaMapping::Offset(KZERO)` convention vminit uses for the DTB) and `port::paqfs` walks the image root, printing one `paqfs: <name>` line per root entry.  With no initrd configured the line is `initrd: none` and the paqfs path never runs.  qemu's `-initrd` is never used: on qemu 11.1.2 it does not deliver for ELF kernels, so xtask places the image with the generic loader and patches `/chosen` into a target/ DTB copy (fdtput, two BE cells per u64).
6. Set up [virtual memory](#virtual-memory) in rust.  (After switching we no longer need the pagetables set up in early initialisation.)
7. Write out the page tables.
8. On virt without `dev_exec`: arm interrupts, then idle in `wfi`.  Under `dev_exec` (04-05): arm interrupts, then run the first-process exec orchestration (below) — it never returns.  On raspi: loop.

### Interrupts (virt)

Device drivers are DTB-discovered, never hardcoded address tables:

- **GICv2** (`platform/virt/gic.rs`): `find_compatible("arm,cortex-a15-gic")` falling back to `arm,gic-400`; GICD/GICC reg blocks mapped via `map_device_register`.  `enable(intid, prio)` does the ISENABLER/IPRIORITYR read-modify-write and writes ITARGETSR (cpu0) for SPIs only — PPIs bank their own targets.  `ack()` reads GICC_IAR, `eoi()` writes GICC_EOIR; the spurious INTID 1023 is acked but never EOI'd.
- **Generic timer** (`platform/virt/timer.rs`): CNTP, PPI 14 → INTID 30.  `CNTFRQ_EL0` is read at runtime on every arm (62.5MHz under TCG, 24MHz under HVF — never hardcoded); the tick handler re-arms TVAL and (04-07) runs the D-13 preemption entry `proc::preempt()` on every tick.  The slice is 1000 Hz (1 ms): the whole userland era runs only a few ms of wall time under TCG, so a slower slice never expires mid-userland (kernel trap/syscall context is IRQ-masked — an expiry while masked is taken at the next eret-to-EL0).  The tick print is `cfg(not(dev_exec))`-gated (04-05, Pitfall 3) and divided down to 1 line/sec so the Phase-3 virt profile's pacing is unchanged.
- **PL011 RX** (`platform/virt/pl011.rs`): INTID 33 (an SPI, so it gets the ITARGETSR write).  `init_rx` arms IMSC=RXIM|RTIM and CR=UARTEN|TXE|RXE; the handler drains the FIFO on FR RXFE and echoes bytes verbatim via raw DR writes — lock-free, because an IRQ-context lock can deadlock against its interrupted holder.

**Ordering rule:** `trap::unmask_irq()` is called LAST, after the GIC, timer and UART RX paths are armed — an IRQ taken before its handler exists falls into the generic trap path (dump + halt).  The idle loop is `wfi`; trap.S's `eret` resumes it after each IRQ.

`trap()` dispatches IRQs from both EL1 and EL0 origins (ack → timer tick (which under dev_exec drives the 04-07 preempt/reschedule) / UART echo → exactly one EOI → return — an EL0-origin IRQ erets back into userland — possibly a DIFFERENT process — through the same shared restore tail) and dumps the full `TrapFrame` (x0–x30, sp/pc/psr/type) for anything else from EL1 — with esr/far printed from live `trap()` locals, not the frame — then prints `kernel halted` and parks in `wfi` — a deterministic stop rather than a silent wedge.  Lower-EL instruction/data aborts route to the demand-fault handler, EC 0x15 (SVC) routes to the real syscall dispatch (04-06; 04-07's RFORK/AWAIT included), and other EL0-origin sync exceptions kill the process loudly.

### Trap frame = Harvey's Ureg (Phase 4, D-05/D-08)

The `handle_interrupt` frame IS Harvey's `Ureg` (`harvey:aarch64/include/ureg.h`) field-for-field — 35 × u64: x0–x28, x29, x30, then `sp`, `pc`, `psr`, `type`; sizeof 280, align(16), so the frame stride stays 288 with the Ureg at the frame base.  One unified frame serves all 16 vectors.  The frame goes on the CURRENT kernel stack — there is no stack switch (04-05; the 9front arm64 shape): EL1h-origin traps build it on the interrupted kernel stack, EL0-origin traps on `SP_EL1` (which `trap_return` leaves at the trapping process's kernel-stack top).  An earlier switch-to-`interruptstackbase` entry clobbered x0 with the stack address before the first store — every frame's x0 held the interrupt-stack top, silently poisoning the SVC number and any EL0-context x0 — and never restored the interrupted EL1 sp on return; the 04-05 runtime gate exposed both.  `sp`@248 is sourced per trap origin: EL0-origin vectors read `SP_EL0`; EL1-origin vectors store the entry sp (`sp`+288 after the frame alloc — on EL1h, `SP_EL0` holds a stale user SP, not a kernel-context value).  `pc`@256 is `ELR_EL1`, `psr`@264 is `SPSR_EL1`, `type`@272 carries the vector index 0–15 (kernel-side informational).  `ESR_EL1`/`FAR_EL1` are no longer frame fields — `trap()` reads them live at entry and passes them as dispatcher arguments, so a stale-frame syndrome read cannot corrupt fault decode.  The restore tail is factored out of line as the exported `trap_return` label (04-05): the macro branches to it after `trap_unsafe`, and exec's first EL0 entry rides it via the `trap_return_exec` wrapper (x0 = the seeded frame → sp, branch in) — the ONLY way EL0 is ever entered; `swtch` never enters EL0.  The restore writes `ELR_EL1`/`SPSR_EL1` from the frame always, and `SP_EL0` only when `frame.psr & 0xF == 0` (returning to EL0t) — an IRQ that interrupted EL1 kernel code never scribbles a kernel address into the user stack pointer, and an EL1h return's `add sp, #288` reproduces the interrupted kernel sp exactly.

The layout is a published cross-repo contract, gated at build time in two layers (D-06): in-crate const asserts in `trap.rs` fail `cargo build` on any drift (always on, no Harvey checkout needed), and `cargo xtask ureg-check` parses the sibling Harvey checkout's `ureg.h` (`$R9_HARVEY_DIR`, default `../harvey`) and fails every boot-test profile on field/order/count drift.  The canonical statement is the "Kernel-side enforcement (Phase 4 appendix)" section of `harvey:aarch64/ABI.md`, which also carries the pinned offset table and the kernel-side argument-read rule (`args at ureg->sp + 8`; `SP+0` reserved).

### Userspace-exec machinery (Phase 4, R9-02/R9-03)

The proc/exec/fault spine is compiled into every build config; 04-05 wired the runtime path (`--config virtexec` = `dev = ["exec"]`): after IRQ arming + unmask, `exec_bootstrap` mounts the initrd paqfs as **devroot** (`port/src/devroot.rs` — attach/walk/open/read/stat over the stateless reader, D-15), sources `/init` through it (walk → open OEXEC — one mechanism), builds the first proc, and `exec_into`s it.  Then the D-10 teardown: the proc's fully-built root table replaces the TTBR0 identity map (`vm::switch(_, RootPageTableType::User)` — closes Phase-3 WR-01; the identity map now exists only for the pre-MMU→MMU transition), the immediate `exec: ttbr0 switched, console alive` print proves all runtime MMIO is TTBR1-side, and `trap::trap_return(frame)` erets into EL0 from the seeded forkret frame.  Serial evidence on the virtexec profile: banner → `initrd: start=…` → `paqfs:` root entries → `ctr_el0: 0x…` (the probed cache geometry) → `devroot: /init open` → `exec: entering EL0 pc=… sp=…` → ttbr0 proof → demand-fault markers → the staged init's syscalls (04-06's real dispatch — see below).  The D-12 experiments (the raspi-gated user-table singleton init and the syscall-exit experiment) are deleted — git history preserves them.

- **Process scaffolding** (`aarch64/src/proc.rs`): `Proc` carries its own 16 KiB kernel stack, its own root page table (one pagealloc'd page per process with the recursive slot-511 self-entry — the pre-04-05 `USER_PAGETABLE` singleton was deleted in 261103-p64, having been dead since the per-process era), a 16-slot fd table, a mapping log (per-mapping va/phys/size/kind for rfork-copy/exit-free), the stashed trap frame pointer, and note/wait/errstr slots.  `PROC_TABLE` is a fixed 8-proc array behind the MCS-lock idiom, taken only briefly in process/boot context — never across the fault handler.  Trap-context code reaches the current proc via `proc::current()`'s `ProcGuard` (261103-p64: the raw-pointer deref lives only in the guard's Deref/DerefMut behind the single-CPU/IRQ-masked invariant; the pointer itself is an `AtomicPtr`, written in process/boot context only).
- **a.out loader** (`aarch64/src/exec.rs`): parses the big-endian Plan 9 header (R_MAGIC arm64 `0x8C47`, 40-byte HDR_MAGIC form, real entry the BE u64 at bytes 32..39) and validates the donor sysexec check set — entry inside text, text+data+bss below USTOP — before any mapping exists.  Exec maps EXACTLY two eager pages (demand-fault-everything, D-09): the top-of-stack seed page and a zeroed Tos page below it, written via their KZERO+PA kernel aliases (the proc's table is not active yet), with `[argc][argv0]…[nil]` + strings laid out per 9front's execregs.  A zeroed TrapFrame at `kstack_top - 288` (R0=tos, SP→user stack, PC=entry, PSR=0 EL0t, LR=0) is the forkret shape: the normal trap-restore path `eret`s into EL0 from it, and the first instruction fetch faults.  r9 owns the user address-space policy (D-11): USTACKTOP = `0x0000_8000_0000_0000`, 16 MiB stack bound, USTOP below it; text/data VAs come from the 7l-fixed header (text maps from 0x10000 with the header included, data at the 64K-aligned VA above text).
- **Demand-fault handler** (`aarch64/src/fault.rs`): trap()'s EC split routes lower-EL instruction/data aborts (EC 0x20/0x24) to `user_fault(frame, esr, far)` — ESR/FAR read live at trap entry, never frame fields.  The faultarm64 class table routes translation/access-flag/permission/TLB-conflict to the demand path; text/data pages are read from the proc's paqfs byte source at byte granularity (text file offset = pageVA − 0x10000; data = (pageVA − data_va) + 40 + textsize) and written THROUGH the user VA (the faulting process's TTBR0 is live — no aliasing, no PAN on cortex-a72), followed by the CTR_EL0-derived `DC CVAU` → `DSB ISH` → `IC IVAU` → `DSB ISH` → `ISB` sequence on the user VA after every text page-in (geometry always discovered, never hardcoded).  bss/stack/tos faults map zero pages; stack growth is bounded at 16 MiB; a fault on an already-mapped page or outside all segments kills the process loudly (print + Moribund + park), and a kernel-context FAR panics loudly (T-04-09).  Evidence markers (`fault: text page-in va=…`, `fault: data page-in va=…`, `fault: stack growth va=…`) prove demand paging on serial.  Page-ins CLAMP the file read to the segment's exact content end (04-06): the paqfs entry's length spans the whole file (syms included), and an unclamped read bled file bytes into the bss window of the last data page — exits()'s `onex[i].f` read `tas.s` as a function pointer before the clamp.  EC-0x15 SVCs route to the real dispatch (below); other EL0-origin sync exceptions take the faultnote-shaped kill path; the EL1-origin panic dump is unchanged.
- **Syndrome decode** (`aarch64/src/registers.rs`): `EsrEl1IssDataAbort` (WnR = bit 6, write-not-read) + `DataFaultStatusCode` mirror the instruction-abort idiom, with lower-EL constructors; host unit tests pin both decoders.

### Syscall dispatch + EXEC (Phase 4 plan 04-06, SC#2)

The EC-0x15 SVC path is real now: `trap()` routes to `syscall::dispatch(frame)` and returns — the shared `trap_return` tail's `ldp x0` pop propagates `frame.x0` to user R0, so the result writeback mechanism is the one that has existed since Phase 3.  The wire ABI is the frozen contract (Harvey `aarch64/ABI.md`): number in R0 (`frame.x0`), args read from user memory at `frame.sp + 8` in 8-byte slots (`SP+0` is the reserved LR slot the stub's `MOV R0, 0(FP)` materializes), result in R0.

- **The measured table** (`aarch64/src/syscall.rs`): `static DISPATCH: [Option<fn>; 55]` over Harvey's frozen `sys.h` numbers 0–54.  The implemented set is exactly the 04-01 donor trace ({pwrite(51), open(14), pread(50), close(4), exits(8)}) plus the D-14 named core's EXEC(7) — zero guessed syscalls (the trace carries no brk_(24)/segbrk(12), so they stay None).  A None entry prints `syscall N unimplemented` and returns -1 — loud, never wedged (D-14).
- **The user-pointer boundary (T-04-11 → T-p64-01, 261103-p64):** every user-VA argument — the Sargs block itself, buffers, path strings, the argv array and each pointed-to string — goes through the **`usermem` module** (`aarch64/src/usermem.rs`): `UserSlice`/`UserSliceMut`/`UserPtr`/`UserString` constructors FUSE `Proc::validate_user_range` (segment membership) with `fault::ensure_user_resident` (the 05-06 cold-buffer zero-page-in), so no call site can ever forget residency again; the raw slice/pointer materializations live ONLY inside usermem behind per-site SAFETY comments (the calling proc's TTBR0 is live in its syscall context).  Two documented `validated_only` constructor variants preserve the pre-usermem validate-without-residency shape exactly where it existed (the Sargs block — resident by construction, the stub wrote through it — and NOTED's saved-ureg window — forced resident at delivery); UNSAFE-AUDIT.md flags the class.  Strings are copied out byte-wise with a bound (ERRMAX); EXEC's argv is bounded at 32 args × 128 bytes.
- **Devices (D-15):** fd 0/1/2 are devcons chans preopened at proc construction.  devcons writes go byte-verbatim through the Console MCS lock + PL011 polled TX (`port::devcons::write_bytes` — no `\n`-cooking on the device path, so user-visible markers originate from the EL0 binary's own pwrite); reads drain a lock-free PL011 RX ring filled by the INTID-33 handler under `cfg(dev_exec)` (the Phase-3 echo stays under `cfg(not(dev_exec))`), returning 0 on empty — no blocking console-read this phase.  The timer tick's `println!` is `cfg(not(dev_exec))`-gated (Pitfall 3): no IRQ-context code ever takes the Console lock once syscalls can print.  devroot chans read via the paqfs reader's `read_at`; OPEN resolves devroot names (component-wise walk from the root) plus the literal `cons`/`#c/cons`; pread/pwrite offset -1 is the streaming channel offset (Pitfall 7 — Harvey libc `write()` IS `pwrite(fd, buf, n, -1)`).
- **EXEC** (`exec::exec_replace`, Plan 9 sysexec semantics): PARSE the new image's a.out header + the seed-fit precheck FIRST (any failure → -1/errstr with the old image intact), FREE the old user mappings second (each leaf entry cleared before its phys page returns to the allocator — a stale translation can never point at a recycled page), SEED third (fresh seed-stack + Tos pages, new segment records and byte source), then REWRITE THE LIVE TRAP FRAME in place (`seed_el0_entry`: R0 = tos, SP → new stack, PC = new entry, PSR = 0, LR = 0).  The dispatch return erets into the new image; success never returns to the old one.  The proc keeps its pid, kernel stack, root table, and fd table (fds survive exec).  The handler returns the new tos_va so dispatch's `frame.x0 = result` writeback agrees with the seeded x0 by construction.
- **EXITS** copies the optional message first, frees the proc's user pages + root-table page + kstack pages (the mapping log + the construction-recorded `kstack_pas`), marks Moribund, prints `process N exited: "msg"`; when no non-Moribund proc remains it prints `all user processes exited` and parks in the clean wfi halt (04-07 turns this into a reschedule).  The kstack/root-table free runs last — the handler executes on that kstack until the park, safe because nothing allocates afterwards in the single-process era.
- **SC#2 execution gate:** `cargo xtask boot-test --arch aarch64 --config virtexec` asserts the ordered chain banner → `exec: entering EL0 pc=0x…` → `init: r9 EL0 alive` → `hello aarch64 harvey` (the committed Phase-2 bisect binary, sha256-pinned in the staging supply chain, printed via the real EL0 svc path) → `all user processes exited`, with an always-on negative scan (`panic`/`Unhandled interrupt` fails any non-panic profile).  The consolidated evidence log lives in Harvey at `.planning/phases/04-r9-userspace-exec-harvey-r9-abi/04-06-sc2-boot.log`.

### Preemptive multi-process (Phase 4 plan 04-07, SC#4 rfork/fd-ops + D-13)

The single-process exec path is now a small preemptive multi-process system: per-process kernel stacks, tick-driven round-robin, RFORK with an eagerly copied address space, and AWAIT/EXITS wait records.

- **Per-process trap stacks (T-04-14, Pitfall 10):** trap.S's entry RECORDS the frame it builds into the `CURFRAME` data symbol, and the `trap_return` tail RELOADS the frame base from `CURFRAME` as its first instruction — a tick may preempt mid-trap, so the tail pops the NEW current proc's frame.  The final stack-pointer step is uniform `frame + 288` for BOTH origins (05-01): every frame the tail restores sits at entry-stack-top − 288 by construction (EL0 entries via the SP_EL1 == current-kstack-top invariant, EL1h entries via the entry's own `sub`, fork/exec seeds via placement), so frame + 288 IS the interrupted kernel stack top — the post-swap CURKSTACK value included.  The pre-05-01 tail instead loaded CURKSTACK through x9 AFTER x9's frame slot had been restored — every EL0t-bound eret resumed userland with x9 = the kernel-stack top, and a tick landing with x9 live destroyed it (the note-timeout/wild-write flake; see the 05-01 section below).  Both symbols are Rust statics in proc.rs written only under the PROC_TABLE lock or in IRQ-masked trap context (single CPU); CURKSTACK remains as proc.rs's record of the invariant — nothing reads it now.
- **Tick round-robin (D-13):** `proc::preempt()` from the timer tick acts only when the current proc is Running (i.e. the IRQ interrupted EL0); `reschedule()` then stashes the live frame (CURFRAME) into the current proc, marks it Ready, and installs the next Ready proc — current pointer + CURKSTACK + CURFRAME + TTBR0 as one PROC_TABLE-locked step — printing one `sched: switch old->new` marker per switch (marker-not-order evidence).  The trap tail's CURFRAME reload returns to the NEW process: IRQ-from-EL0 + return-to-a-different-process is exercised, not deferred to Phase 5.
- **swtch (rewritten):** the pre-existing aarch64 swtch.S was never called and could not round-trip (it pushed x19..x30 in the same order it popped them — on a descending stack every register resumed from a different slot — and sourced SPSR/ELR from stack garbage via a trailing eret).  It is now a symmetric struct save/restore against `swtch::Context` ending in `ret`, used ONLY for kernel-context (blocked mid-syscall) switches; EL0 entry/exit never rides swtch.
- **Blocking syscalls (the machinery 04-08's notes and Phase 5's real init stand on):** AWAIT marks the proc Blocked and `proc::sched()` swtch'es into the scheduler context (`sched_loop` on the legacy interrupt stack, seeded on first use).  The sched loop's `pick_next` applies the same locked CURKSTACK + CURFRAME + TTBR0 + current swap BEFORE resuming a proc, then resumes a blocked-mid-syscall proc via swtch (its saved `Proc.context`) or any other Ready proc via `trap::trap_return(frame)` — the only EL0 entry.  Nothing Ready → wfi with IRQs briefly unmasked; the post-wfi re-scan dispatches.
- **RFORK(19)** (`proc::rfork_clone`): donor sysrfork flag validation (rejects (RFFDG|RFCFDG), (RFNAMEG|RFCNAMEG), (RFENVG|RFCENVG) together, and RFMEM|RFNOWAIT without RFPROC); RFPROC required, supported bits ⊆ {RFPROC, RFMEM, RFFDG, RFNOWAIT, RFREND}, everything else a loud -1 errstr.  The child gets a fresh proc (new kstack + root table), an EAGER page-for-page copy of every user mapping (no COW, no shared writable pages — T-04-15; the donor's RFMEM share-semantics is deliberately not honoured), a dup'd fd table (fresh Chan values — `Chan::dup`), mirrored segment records + paqfs byte source, and a copy of the parent's live frame on its own kstack with x0=0 (donor forkchild).  Parent's wire result is the child pid.
- **AWAIT(47)/EXITS wait records:** EXITS (unless the child was rfork'd RFNOWAIT) posts a wait record into the parent's PROC_TABLE slot queue and wakes a Blocked parent (Blocked → Ready); AWAIT consumes records in post order and formats the Plan-9-shaped `{pid} 0 0 0 "{msg}"` message into the validated user buffer, blocking via `sched()` when a child is still live and erroring `no children` otherwise.  EXITS of the last active proc keeps the 04-06 all-exited marker + clean wfi halt; otherwise it frees (kstack LAST — the swtch save writes only the table-resident context, never the freed stack) and hands off to the sched loop.
- **Arg-width discipline (donor-faithful):** 7c materialises int/uint-width arguments with a 32-bit store into the 8-byte slot, leaving the upper half as stack garbage — the donor's `va_arg` reads only the slot's low half for a 4-byte type (9front arm64/include/u.h: `sizeof(mode)==4` selects `((mode*)list)[-2]`), so handlers mask int-width args to 32 bits (await's buflen, errstr's n, rfork's flag, the fd args, open's mode).  Caught by the first virtmulti run: await's buflen arrived as `0x7fff0000007f`.  ERRSTR(41) joined the dispatch table for libc's `%r` (rerrstr calls it twice) — a measured caller, not a guessed one.  **`long` is 32-bit in Plan 9 C on every arch (7c `SZ_LONG=4`; only `vlong` is 64-bit), so pread/pwrite's `long n` is masked too (05-01)** — the D-15 stacksmoke's deep recursion left pointer garbage in the reused stack pages and the unmasked n read as a ~128 TiB write, failing validation and silently dropping print() output; shallow stacks never saw it (fresh demand-paged pages are zeroed).
- **virtmulti profile:** `aarch64/lib/config_virtmulti.toml` is byte-identical KERNEL config to virtexec (same `dev = ["exec"]` cfg, same initrd); only the xtask assertion set differs, selected by config NAME (documented beside the BootTestStep selection idiom).  The staged init rforks child A (exec /hello) + child B (exec /smokefork) and awaits both; smokefork verifies /hello's R_MAGIC header via open/pread/close (fd-ops smoke) then rforks + awaits its own child.  Assertions: banner → exec entry → init print (ordered), then the five smoke markers EACH AT LEAST ONCE + ≥ 1 `sched: switch` line (unordered, D-13), then all-exited — plus the always-on negative scan.

### Notes + devproc-lite (Phase 4 plan 04-08, SC#4's notes half)

The last syscall family the shell-era binaries need: Plan 9 notes (async messages between processes).  There is NO postnote syscall — libc `postnote(PNPROC, pid, msg)` opens and writes `/proc/<pid>/note`, so the note arrives by a device write.

- **devproc-lite** (`port/src/devproc.rs`): the D-16 hard scope — it serves per-process note files and nothing else.  Walk accepts a numeric pid component under the root, then the literal name `note`; every other name is a walk error.  Open is write-only on a note chan; write decodes the target pid from the chan's qid, bounds the message to ERRMAX (NUL-terminated copy), and hands it to the arch-side post hook (`proc::post_note` — registered at boot via `set_post_hook`, the same dependency inversion as devcons's `Console::set_uart`, because the proc table lives in the arch crate).  The write resolves ONLY the addressed pid (T-04-17 — no broadcast, no group semantics).  libc postnote runs unmodified.
- **NOTIFY(28)/NOTED(29)** (the dispatch table's notes pair): NOTIFY validates the handler VA is 4-aligned and inside the proc's OWN text segment (T-04-17 — a process can never install a handler pointing outside its image), then stores it on the proc (nil clears; rfork inherits it, exec clears it + the queued notes — donor newproc/sysexec semantics).  NOTED takes the action: NCONT(0)/NRSTR(3) copy the saved Ureg — the frozen 280 bytes, NOT r9's 288 frame stride (Pitfall 6's field-offsets-only crossing rule) — over the live frame in place after validating the resume pc/sp (the source pointer is kernel-tracked, the donor's `up->noteureg`, because libc's `noted(action)` passes no pointer); NDFLT(1) exits with the note message; NSAVE(2) is loud-unimplemented.  NOTED's success takes the dispatcher's special return path: dispatch returns WITHOUT the `frame.x0` writeback, because the handler already rewrote the frame (the donor `dosyscall` NOTED case).
- **Delivery at the return-to-EL0 boundary** (`trap.rs`'s `deliver_notes`): one check placed on BOTH return paths — after syscall dispatch AND after a handled IRQ — guarded by `frame.psr & 0xF == 0`.  The IRQ path resolves `proc::current_frame()` (CURFRAME) rather than the entry frame, because a tick may have preempted mid-trap: the proc about to return to EL0 is the CURRENT one, and CURFRAME is the frame the tail actually restores.  The construction is the donor `notify()` verbatim: push a 256-byte debug preserve + the 280-byte Ureg copy + the note string (ERRMAX slot) + the arg homes `[sp+8]=nureg, [sp+16]=&msg` onto the USER stack, then `frame.x0=nureg, frame.pc=handler, frame.link_register=0` — libc's `void f(void *ureg, char *msg)` handler signature is satisfied exactly (the smoke's `noted(NCONT)` path — `notejmp.c` — edits the saved ureg's r0/pc/sp and resumes).  T-04-16 (the donor okaddr port): the whole write window is validated user-writable via `validate_user_range` BEFORE any write and forced resident (`fault::ensure_stack_resident` — an in-segment-but-unmapped page would EL1h-abort mid-delivery); an unwritable/misaligned target or a missing handler kills the process loudly with the note printed (the exits path), never a partial write, never a kernel write to a bad user VA.

### Virtual Memory

VM initialisation proceeds as follows:
1. Set up the page allocator.  We use a bitmap allocator defined in `pagealloc.rs`.  This makes use of the `earlypages` reserved in the `kernel.ld` linker script.  The 16KiB reserved here allows us to manage 16\*4096\*8 pages.  Each bit represents 4096KiB, allowing us to map 2GiB of RAM.  The allocator assumes everything except the early pages are allocated at first.  This is to ensure we don't mistakenly allocate a page that should not be available (e.g. will be mapped below).
2. Build an initial memory map.  The mapped ranges are per-platform (`base_physaddr()`): virt starts kernel ranges at the linker's `boottext_pa` (`0x40080000`, so the GIC/PL011 MMIO windows never become Normal-cacheable kernel text) and maps kernel text with 4K pages (the load address is not 2MiB-aligned); raspi keeps base 0 and 2MiB pages.  Both map:
   - Device tree DTB
   - Kernel text, data and BSS
   - MMIO
3. We map each of the above ranges according to the defined entry flags.
4. We now mark all the unallocated pages free.

### paqfs

`paqfs.rs` is a `no_std` reader for Plan 9 paqfs/bootfs images (Harvey `sys/src/cmd/paqfs/` is the producer + reference reader), over a memory-resident `&[u8]` — the initrd root-fs format.  It parses the 44-byte header (magic `0x529AB12B`, small form only), the 28-byte trailer (magic `0x6B46E688`, root DirBlock offset; the sha1 is not verified), and 12-byte block headers (magic `0x198A1CBF`, type Dir/Data/Pointer, encoding NoEnc/DeflateEnc).  NoEnc payloads are always blocksize bytes on disk; DeflateEnc is raw RFC 1951 inflate (`miniz_oxide`, output hard-capped at blocksize), and every block's adler32 header field is checked against the DECODED payload — note Harvey's libflate `adler32(0, …)` is the seed-0 variant, reproduced via `adler2::Adler32::from_checksum(0)`, not the RFC 1950 seed.  The API is stateless-per-call (`open_image` / `read_block` / `root_dir` / `read_dir` / `walk` / `read_at`): no statics, no locks, all offsets bounds-checked before slicing, every failure a typed `Err` — reentrant by construction so the future demand-fault handler can call it in trap context.  Host tests (`port/tests/paqfs_test.rs`) verify byte-level against the committed mkpaqfs fixture `port/tests/fixtures/probe-tree.paq` plus a synthetic in-test image, including corrupt-input negatives.

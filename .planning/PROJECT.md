# r9

## What This Is

r9 is a faithful pure-Rust port of Bell Labs' Plan 9 and Harvey (the 64-bit Plan 9 4th Edition derivative). The Rust kernel already boots Harvey's C userland on QEMU q35 x86_64 (primary) and aarch64 virt (HVF/TCG). The work ahead replaces Harvey's C userland with Rust one binary at a time, brings the kernel up on multiple CPUs, adds a native encrypted 9P wire protocol (`9P2000.aead`) with distributed extensions, then makes r9 self-hosting so Harvey can be archived. The owner is the sole product owner and works with a single implementer.

As of v3.0 (2026-11-25) the cross-build harness, the design lock, `crypto/`, `ds/` and the `9P2000.aead` wire foundation exist and are pinned by host tests. The booted kernel still speaks plain 9P2000; the authenticated engine is selected only at mount negotiation by a peer that offers `9P2000.aead` (D-16/D-23).

### Out of Scope

- POSIX emulation calls, `mmap` extensions, or any new syscall — the system call list is closed (IG-D03); software adapts to `rfork`, `bind`, `mount`, 9P
- Kernel loading of ELF — `a.out` is the sole executable format (IG-D02); in-tree tooling converts linker ELF
- Physical DRAM bus probing, cold-boot attacks, and arbitrary code execution in kernel context — outside the threat model (AC-T01); AMD SEV-SNP or Intel TDX is the remedy if bus sniffing is ever added
- Funnel Hashing on primary paths (page cache, FidTable, Venti index) — restricted to write-once ephemeral scratchpads (IG-D09)

## Constraints

- **Tech stack**: Pure Rust, `no_std` kernel, pinned `nightly-2026-01-30`, targets `x86_64-unknown-none` (primary), `aarch64-unknown-none`; Harvey C is the userland bootstrap only until Track P retires it
- **Runtime**: QEMU q35 x86_64 primary; aarch64 virt under HVF and TCG; the golden invariant is checked on q35
- **Golden invariant**: boots to rio on QEMU q35 at every commit; Track P replacement is one binary per commit (IG-V02 risk 4)
- **Compatibility**: `a.out` only; closed syscall list; one extension flag, `RFNOLEGACY` (`1 << 18` after CORR-04), and zero syscalls. `RFCKEY`, `RFROBASE` and `RFRANDMEM` are retired (owner, 2026-11-25); until CORR-04 lands the tree still defines four bits at 18 to 21
- **Safety**: every `port/` module carries a per-module `forbid(unsafe_code)` except the three named modules `globalalloc`, `mcslock` and `devip_waker`, and no new such module is added without owner approval; `crypto/` is crate-level `forbid(unsafe_code)` over r9's own code, not the pinned crates it wraps; `ds/` uses per-module forbids with exactly two places that may hold `unsafe` — `ds/src/tpht/` and one reserved Roaring SIMD module with no code until Phase 5 — and a third needs owner approval; the workspace lint `undocumented_unsafe_blocks = deny` is opted into by `aarch64`, `port`, `crypto` and `ds`; low-level operations (`WRPKRU`, `MOVNTDQ`, `CLFLUSHOPT`, inline asm, raw atomics) stay in `x86_64/`, `aarch64/`, and `ds/src/tpht/` behind audited `// SAFETY:` blocks (IG-D07; W5 and note N2 settled for the two new crates on 2026-11-24)
- **Kernel FP/SIMD**: kernels are built without FP/SIMD; kernel SIMD goes through `fpu::kernel_begin()` / `with_simd()`; user FP state is per process; arm64 is the reference for x86_64 (owner rule)
- **Verification discipline**: every phase follows committed RED pin, implementation, GREEN verification twice, pin advance (IG-V01)
- **Audit ledger**: the guide's 17 corrections must stay permanently corrected in all later PRs (IG-A01)
- **Process (owner standing rules)**: pushes in either repo need explicit owner approval; edits under `port/src` need owner approval (show the diff first); `aarch64/`, `x86_64/`, `xtask/` edits do not; an x86_64 kernel byte change needs the `boot-iso` `outputHash` re-derived and committed, the x64 TCG gates in an amd64 Docker container (cleaned up afterwards), and the owner's linux boot-iso check; an aarch64 kernel byte change gets a quick pass now and the full HVF series at Phase 8; once `boot-iso` is a pure derivation (CORR-02), green CI on the commit replaces the x86_64 hash-and-owner-check procedure (owner, 2026-11-25)
- **Scope discipline** (v3.0 guide rule 4): no phase reintroduces software RAM encryption, `PKEY`/`WRPKRU` page-fault hooks, or Rust rewrites of `6c`/`6a`/`6l`; a proposed deviation is recorded as an owner decision in `.planning/` first. From Phase 5 on, new kernel boot gates run with `-smp 2` on q35 and virt
- **Commits**: no AI attribution in commit messages or PR bodies, anywhere

**Roadmapper notes (new; not part of the owner-approved eleven; raise at the named phase).**

- **N1** (Phase 3, Phase 4): the RFC specifies ChaCha20 "with 64-bit block counters and 96-bit nonces" (RFC section 3.1). ChaCha20's state has 128 bits for counter plus nonce; 64 plus 96 is 160. RFC 8439, which the RFC cites, uses a 32-bit counter with a 96-bit nonce, and the wire carries an 8-byte sequence nonce while AC `TagEntry` carries a 12-byte nonce. The exact counter/nonce construction needs fixing before ChaCha20 vectors are pinned. **Settled for the cipher layout on 2026-11-24** (Phase 3 CONTEXT D-06): ChaCha20 uses the RFC 8439 layout, a 32-bit block counter and a 96-bit nonce, pinned to RFC 8439 sections 2.3.2 and 2.4.2. The rule extending the 8-byte wire sequence nonce to 12 bytes stays open for Phase 4. **Fully settled on 2026-11-24** (Phase 4 CONTEXT D-08): the 12-byte ChaCha20 nonce is a 4-byte prefix derived per connection and per direction from the `Tauth` key derivation, followed by the 8-byte wire sequence nonce; the prefix is not sent on the wire.
- **N2** (Phase 3, Phase 5): IG-D07 and IG-V01 describe `port/` as crate-level forbid, `undocumented_unsafe_blocks = deny` on arch crates, and an audit covering `x86_64/src/shadow.rs` and `cryptpage.rs`. HEAD differs: per-module forbids with three floor modules, `x86_64` not lint-opted-in, audit scoped to aarch64 and port. Decide how to extend lint and audit scope when new unsafe lands. **Settled for `crypto/` and `ds/` on 2026-11-24** (Phase 3 CONTEXT D-09 to D-11): `crypto/` is crate-level `forbid(unsafe_code)` over r9's own code, `ds/` uses per-module forbids with `ds/src/tpht/` as the unsafe-holding module and one reserved Roaring SIMD module, both crates take `[lints] workspace = true`, and `UNSAFE-AUDIT.md` gains their entries. It stays open for `x86_64` in Phase 5. **For `x86_64` it is now CORR-05 in Phase 5 (2026-11-25).**
- **N3** (Phase 2, informational): AC section 1.1 says bits 18-20 are already reserved in Harvey `sys/include/libc.h` and `x86_64/src/proc.rs`. That is not true at HEAD. The highest `rfork` bit in use is 14 (`RFNOMNT`, Harvey `libc.h:624`); at roadmap time r9 defined bits 0-6 and 10-13 in two arch-local copies; nothing in either repo uses bits 15-21. Harvey is not edited: the owner's 2026-11-22 decision overrides the guide's "reserve bits 18-20 in `libc.h`" and is recorded as a deviation from the guide. Nothing in Harvey's C userland uses the new bits, so no Harvey-side definition is needed.
- **N4** (Phase 1, Phase 16): the "boots to rio" proof and the other composed gates live in Harvey's flake, not in r9's xtask. Owner direction 2026-11-22 (HARN-08): Phase 1 flips flake ownership, so r9's flake imports Harvey and produces the composed boot and gate outputs, and Harvey's flake drops its `r9` input. The second, page-level check at fault time stays open for Phase 5. **The fault-time half is void since 2026-11-25: frames are verified and decrypted on receive.**

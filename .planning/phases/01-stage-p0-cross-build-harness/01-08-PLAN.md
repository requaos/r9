# Plan 01-08: Tracer — the per-architecture resolver and the manifest engine boot the aarch64 smoke image

<objective>
Planning pass 2 (D-22) begins here. This plan carries the phase's tracer: the thinnest production path through every xtask layer the phase changes. The path is the resolver, then a per-file manifest, then the stage-and-bake engine, then an existing boot-test profile, on the one image the Mac can boot end to end today: the aarch64 smoke initrd that `virtexec` boots under HVF. Why aarch64 and not amd64: a tracer needs a real `<verify>` the executor can run, and x86_64 ISO composition needs grub2/xorriso, which r9's devshell provides only on Linux. An amd64 tracer would only be checkable at an owner stop, so it could not give early feedback. The supply in this plan is the manual override (`R9_HARVEY_DIR` at the owner's pre-built checkout, read-only). That is a permanent, supported path under D-21, not a stub. Plan 01-13 swaps in the flake supply (`R9_HARVEY_DIR_ARM64`) without changing xtask's architecture.

Task 2 completes HARN-02: precedence, the named error, `HARVEY_SRC`, `vendor/harvey/`, realise-on-first-use, and routing of all seven consumer sites.

Purpose: prove resolver -> manifest -> bake -> boot before any flake work, and settle the resolver contract every later plan uses.
Output: `xtask/src/harvey.rs`, `xtask/src/image.rs`, `xtask/manifests/arm64/smoke.toml`, and rewired consumers.
</objective>

<assumption_delta_decision seam="single Harvey tree variable -> per-architecture trees" decision="promote">
The owner already decided this (D-21). The per-architecture tree (`R9_HARVEY_DIR_AMD64` / `R9_HARVEY_DIR_ARM64`) is the primary identity. `R9_HARVEY_DIR` is demoted to a manual override that still wins when set, and `HARVEY_SRC` is an explicit alias with the lowest precedence. An invariant test enforces it: every consumer resolves through the per-arch resolver for both architectures. A source test fails if any xtask source file outside `harvey.rs` reads one of the variables directly, or keeps a zero-argument resolver.
</assumption_delta_decision>

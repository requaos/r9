# Plan 01-18: The quick gate — `cargo xtask gate` with the rio leg, and the drawterm gate moved into r9

<objective>
This plan delivers HARN-01: one documented `cargo xtask` command that boots r9 on q35 from the r9 kernel and the pre-built Harvey tree, proves rio is serving, and exits non-zero otherwise. Per D-11 the proof is the existing drawterm gate extended with rio. The gate script and expect driver therefore move into r9 first (D-07). They are rewired so the read-only tree and r9's assembler replace Harvey's in-checkout build and bake, and they gain the rio leg with the feed proven at stop A (D-28), the unchanged control-noG, and the failing-direction mode. `cargo xtask gate` orchestrates the quick tier (D-14) and checks afterwards that the tree is unmodified (HARN-02). `--full` runs the moved apps once plans 01-21, 01-30, 01-23, 01-24 and 01-31 have moved them.

From this plan on, D-12 applies. The quick gate is run before each commit lands. On the Mac it can only be checked statically and with unit tests, because x86_64 ISO composition is Linux-only. The KVM witness runs are batched at owner stops (stop B first, plan 01-22).

Purpose: the golden invariant becomes an r9-owned command.
Output: `nix/gates/drawterm-gate-x64.sh`, `gates/x86_64/drawterm-gate.expect`, the `drawterm-gate-x64` app, and `xtask/src/gate.rs`.
</objective>

The quick tier, x86-64 only, does this in order:
1. Resolve the amd64 tree with `harvey::harvey_dir(Arch::X86_64)` (realising on first use). Record the tree identity: store path, or `tree_digest` for a non-store override.
2. Assemble image:cpu through the image engine, with its drift checks.
3. Build the kernel with `--config q35cpu` through BuildStep, and compose the ISO with the image module and the profile's append through the same code DistStep uses for q35cpu.
4. Run `expect gates/x86_64/drawterm-gate.expect` twice, with `GATE_MODE=rio` then `GATE_MODE=control-noG` (or once with `force-no-rio`). Logs go to `target/gate/<run-id>/<leg>.log`.
5. Check the tree is unmodified: `nix store verify --no-trust <path>` for store paths, or a recomputed digest for an override. On change, fail with `GATE-FAIL harvey-tree-modified`.
6. Print `GATE PASS quick x86_64 run=<id>` and return Ok. Any failing leg returns Err with that leg's GATE-FAIL marker, so the top-level handler exits 1.

`--full` checks each listed app exists (`nix eval .#apps.<system>.<name>.program`), naming any missing one, then runs `nix run .#<name>` for each in order, records PASS/FAIL per app in `target/gate/<run-id>/full.tsv`, and fails if any app failed. Add the behaviour tests.

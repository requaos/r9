# Plan 01-34: Stop-C fixes — tap seam, capture paths, and the fpprobe note-delivery investigation

<objective>
Stop C exposed two harness defects and one real gate failure. The soak/stress
preflight ran net-doctor from the r9 root without HARVEY, so the tap venue was
never exercised. The full runner copied `target/gates/<app-name>` while the apps
write `target/gates/<short-name>`, so six equivalence rows were `-1` and
`boot-r9-x64` had no per-app log. The real failure is `boot-r9-tier1-x64`
`T1-FAIL fpprobe`: the note handlers never ran and the user trap vector 1 was
unhandled.

This plan fixes the two harness defects and investigates the fpprobe failure
from evidence. If note delivery can be fixed in this phase, the tier1 gate runs
its real handlers; if it is a known kernel gap, the finding names the exact next
action and a re-scope recommendation for the owner. The Harvey diff remains
unapproved and uncommitted until a green stop C and an explicit APPROVE.
</objective>

# Plan 01-09: Rio de-risk preparation — find the headless credential path and fix the feed (D-28)

<objective>
HARN-01 depends on proving rio is serving without a display, and pass 1 never proved that (D-28). The S3 rio leg reached `cpurc: DONE` and started drawterm under Xvfb. It then timed out at the `dt-password` feed stage. The `tr-ok` line in its capture was the owner's own graphical login, not gate evidence. This plan does the first rio work D-28 requires, as an explicit early de-risking step:

- determine the generated DEMO credential path;
- determine where drawterm actually reads its password when it uses the X11 backend;
- fix the headless authentication and password feed in a pass-2 copy of the S3 harness;
- build the reusable witness driver the owner runs at stop A (plan 01-12), which re-runs the rio leg on the KVM witness (D-13).

The S3 harness bakes with Harvey's own `mkimage.sh` on a scratch Harvey copy. That makes it the fastest way to prove headless auth before r9's own cpu image exists. Plan 01-18 later ports the proven feed into r9's quick gate.

A static lead to check first, not to assume: Harvey's drawterm `readcons()` (`sys/src/cmd/unix/drawterm/readcons.c`) opens drawterm's own `/dev/cons`. Under a GUI backend, that console may take input from the window's keyboard and not from the pty. If so, the pty feed can never reach it.

Purpose: remove the single largest risk to HARN-01 before the r9 gate is built on it.
Output: `rio-derisk/` (findings, flake, gate script, expect driver) and `witness/` (driver, README).
</objective>

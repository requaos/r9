## Goal Achievement

The phase's central wire is real and the host tests pass, but the goal is **not fully achieved** once the concurrent code review (`04-REVIEW.md`) is read against the code.

What is achieved:

- The 28-byte `9P2000.aead` header with `Pad` and `ExtTLVs Length` inside the authenticated AAD, the full 100–139 opcode registry, all 27 base bodies plus the eight RFC 6.2 pairs and the re-key pair, six `ExtMask` bits parsed zero-copy, and the D-09 parameter-then-paged data bodies exist and are pinned (`port/src/chan/{wire,msg,tlv,transport}.rs`).
- A sealed packet verifies the MAC over `[0, size - 32)` before reading any field but `Size`; every altered byte closes and zeroizes with zero packets decoded; a repeated/skipped/earlier sequence closes; replayed, cross-connection and reflected packets are refused. I re-ran `nix develop -c cargo xtask test-9p`: exit 0, 14 `test result: ok` lines, all five `port` files and both `crypto` session legs on default and scalar backends.
- The single-read resolve is one `deref_tiny` read with zero header reads (`(arena_reads, header_reads) == (1,0)`), the `StatelessCap` verifier touches no shard or bitmap, and the plain `devmnt` path is unchanged (`devmnt_test` 18/18 passed).

What is not achieved (details in Gaps and the code-review cross-check):

- **CR-01:** the in-band exchange secret is not zeroized by `Rekey::fail`, and `Session::keys_zeroized()` omits it; a failure/teardown between the seam's `Done` and `finish_exchange` leaves a live 32-byte secret while the public query reports "all zero". This contradicts WIRE-03/WIRE-05 and the "every key the session holds" truth.
- **CR-02:** exchange messages are indistinguishable from ordinary traffic. `rekey_step` has no tag/fid; ordinary `Twrite`/`Rwrite`/`Tread`/`Rread`/`Tauth`/`Rauth` are absorbed or close the connection, and the exchange tags collide with devmnt's allocator. The in-band re-key cannot coexist with a live mount.
- **CR-03:** the re-key transcript absorbs page-padded data, contradicting DECISION P2 (data unpadded, padding not hashed); the independent pin mirrors the bug.
- **WR-01/WR-02/WR-07:** a connection can re-key only once; `SendHalf::send` ignores the ACK deadline; the re-key control messages use tag 0 instead of the pinned `NOTAG`.
- **WR-04/WR-05:** a torn clunk can resolve an all-zero identity, and a sweep can remove a live entry that reused a swept slot.

The code review was produced concurrently with this verification. I independently confirmed each critical and the named warnings by reading the cited code; the passing tests do not cover those paths. No `04-REVIEW-DISPOSITION.md` exists, so none of the findings is an accepted deviation.

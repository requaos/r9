# Plan 04-15: The end-of-phase owner stop — x86_64 byte-change procedure and boot to rio, then `main`

<objective>
Everything that needs the owner's x86_64 Linux host happens at one stop, in the order of `04-OWNER-STOP.md`: the owner approves the branch push, runs the host tests, builds the sandboxed kernels, re-derives and commits the `boot-iso` `outputHash`, runs the KVM gate, the native TCG gate and the full gate set, and reports back. The executor records the verdicts, and `main` is pushed only after a second approval.

Purpose: D-25's byte-change procedure and the golden invariant, which the Mac cannot prove.
Output: the pushed branch, the owner's hash commit, `RESULTS.md`, and, after approval, a pushed `main`.
</objective>

## Rules that bind every task in this plan

- Commit messages carry no AI attribution line of any kind.
- Every push needs the owner's explicit approval for that push. The executor checks what is unpushed first and pushes only what was approved.
- The Mac cannot build the sandboxed kernel derivations, cannot run KVM and cannot reach the owner's host. No verdict for those steps is produced here.
- Between the branch push and the return, make no commit on the Mac, so `main` can take the branch by fast-forward.
- This plan runs on the main working tree with `main` checked out. Each task first checks that `git rev-parse --abbrev-ref HEAD` prints `main` and that `git rev-parse --path-format=absolute --git-dir` equals `git rev-parse --path-format=absolute --git-common-dir`; if not, it pushes nothing, commits nothing and returns `## CHECKPOINT REACHED` saying the plan must be dispatched on the main working tree (`workflow.use_worktrees` off for this wave).
- `P` below is `.planning/phases/04-guide-phase-2-9p2000-aead-transport-and-fidtable`. The branch is `phase-04/aead-wire`.

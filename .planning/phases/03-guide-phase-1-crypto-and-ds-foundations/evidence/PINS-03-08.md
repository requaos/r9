# Pin ledger: the TPHT spill path and the measured spill threshold (plan 03-08)

Two pin ids: `tpht-spill` (the spill into `ChainedTphtOverflow` under the home
block's seqlock: DS-01, D-13) and `tpht-hit-rate` (over 90% of present-key
lookups resolve in the home block at the chosen occupancy, for every grid
distribution: DS-01, D-15).  Each records RED, GREEN-1, GREEN-2 and ADVANCED
per IG-V01 (CONTEXT D-02).  `REPIN` names every test of plans 03-06 and 03-13
that this plan edits, with what changed (IG-V01: a pin is changed on purpose
and by name).  `MIRI` records the result line of
`nix develop -c cargo xtask miri` (64 seeds) and `MIRI-TIME` the measured whole
seconds of one warm run; the budget is 120 seconds (03-VALIDATION.md, "Max
feedback latency").  `MIRI-OVER` records a run above the budget before a
resize.

## Task 1 — the spill path

The six tests below were advanced by plans 03-06 and 03-13.  Each moves from
`new(n)`/`with_probe(n, p)` to a home-only shard (`with_banks(n, 0)` /
`with_banks_and_probe(n, 0, p)`), unwraps `insert`'s new
`Result<Option<TinyPtr>, TphtError>` as `Ok(Some(ptr))`, and reads `lookup`'s
new `Found` through `Found::value`/`Found::home`.  What each asserts is
unchanged; `home_ops_match_btreemap_model` gains the two placement assertions
the new API makes possible.

REPIN tpht-shard fingerprint_collisions_are_verified — constructor to `with_banks(1, 0)`, both inserts unwrapped as `Ok(Some(ptr))`, lookups compared as `Found { value, home: Some(ptr) }`; the collision, the two values and the distinct pointers are asserted as before

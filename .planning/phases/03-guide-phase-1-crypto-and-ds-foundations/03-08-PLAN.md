Step A, the rule, committed before any measurement. Create `P/evidence/SPILL-THRESHOLD.md` with the definitions and the rule, and commit it alone, message `evidence(03-08): spill-threshold measurement method and selection rule`:
- Occupancy is entries inserted divided by 16 times the number of blocks. A lookup of a present key is a home-block hit when it resolves from the home header without touching a bank. The spill threshold `T` is the number of header slots a block may use before further keys of that block go to the banks, `1 <= T <= 16`.
- Grid: `T` in 4, 8, 12, 14, 15, 16; occupancy in 0.50, 0.70, 0.80, 0.85, 0.90, 0.95, 1.00; five key distributions (uniform random `u64`; sequential `0..n`; `PageKey`-style `(image_id << 32) | page_offset` with 64 images and sequential pages; `id << 32`; `(id << 32) | 7`); three literal seeds; 16,384 blocks.
- Reported per cell: the home-hit fraction for present keys and the fraction of absent-key lookups that end at the header, for the mixed-half index; and the home-hit fraction for the unmixed low-bits index (compendium 4.1 as written) from the counting model.
- One arithmetic for the grid and the pin, in `ds/src/tpht/measure.rs`: `entries_at(blocks, occupancy)` gives the number of keys inserted for an occupancy; `exceeds_bar(hits, lookups)` is the bar, the exact integer test `hits * 10 > lookups * 9`; `banks_for(entries)` gives the bank count of a measured table, twice the number of 255-node banks that would hold every entry and at least 2, so that no insert fails with `BanksFull` at any `T`. The harness asserts every insert returned `Ok`, is single-threaded, and uses a seeded generator with wrapping integer arithmetic, so a run is a pure function of (distribution, seed, blocks, occupancy, `T`). Printed decimals are for reading; qualification never uses them.
- Selection rule: a pair (`T`, occupancy) qualifies when `exceeds_bar` holds with the mixed-half index for every distribution and every seed, that is, the home-hit fraction is above 0.90 in all fifteen runs. `HIT_RATE_OCCUPANCY` is the highest occupancy in the grid for which some `T` qualifies. `SPILL_THRESHOLD` is the smallest `T` that qualifies at that occupancy. If no `T` qualifies at any occupancy of 0.85 or above, nothing is chosen: stop and return the table to the owner. The generator applies the rule in code and prints its result; the rule is not applied by reading rounded figures.
- The pin and the rule: the pin `hit_rate_home_block_exceeds_90_percent` re-runs the chosen cell. It uses the grid's 16,384 blocks, three seeds, five distributions and key generators, with `entries_at`, `banks_for` and `exceeds_bar`, on a shard built by the production `with_banks`, so the threshold in force is the production constant. Because a run is a pure function of its inputs, the pin's fifteen counts equal the chosen cell's fifteen counts, and a cell that qualified passes the pin. This is fixed here, before any measurement.
- No margin: the bar is not raised above 0.90 and no occupancy is skipped, so the choice keeps D-15's meaning, the highest occupancy at which a threshold is over 90%. What the choice rests on is recorded instead: a line `MARGIN hits=<h> lookups=<n>` for the weakest of the fifteen runs of the chosen cell, and the same `T` at the next occupancy up the grid (when there is one), shown with its counts so the owner can see how far it fell short. RESEARCH F9's model puts `T = 16` at 0.901 for occupancy 1.00 and 0.922 for 0.95; if the measurement chooses a cell that close to the bar, the `MARGIN` line shows it, and the pin still passes because it is the same computation.

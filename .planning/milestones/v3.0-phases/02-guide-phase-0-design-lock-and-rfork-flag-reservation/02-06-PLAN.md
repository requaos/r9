# Plan 02-06: The single end-of-phase owner stop — branch, hash commit, x86_64 host tests, gates, then `main`

<objective>
Everything that needs the owner's x86_64 Linux KVM host happens at one stop, in one ordered checklist (`02-OWNER-STOP.md`): the owner approves the branch push, pulls, runs the x86_64 host tests, makes the `boot-iso` `outputHash` commit and proves it with a build and `--rebuild`, runs the boot-to-rio quick gate once under KVM, the TCG gate, and the full gate set, and reports back. The executor records the verdicts from the return, and `main` is pushed only after a second owner approval.

Purpose: the x86_64 kernel byte-change procedure as planned work (D-23), the x86_64 host-test witness (D-24), the phase's one gate run (D-25, D-27), the order inside the stop (D-29), and the transport and push rules (D-26, D-28).
Output: the pushed branch, the owner's hash commit on `main`, `RESULTS.md`, and, after approval, a pushed `main`.
</objective>

## Rules that bind every task in this plan

- Commit messages carry no AI attribution line of any kind, including the commit the owner makes on the Linux host.
- Every push needs the owner's explicit approval for that push. The executor checks what is unpushed first and pushes only what was approved.
- The Mac cannot reach the owner's host and cannot run the gate (`GATE-VENUE not-linux`) or the x86_64 host tests. No verdict for those is produced here.
- Between the branch push and the return, make no commit on the Mac, so `main` can take the branch by fast-forward.
- Harvey is read-only.
- Execution mode. Required setting for Phase 2: `workflow.use_worktrees` = `false` in `.planning/config.json`, set by the operator before the phase is run with `node "$HOME/.claude/gsd-core/bin/gsd-tools.cjs" query config-set workflow.use_worktrees false`, or set `"use_worktrees": false` under `"workflow"` in `.planning/config.json` by hand (also stated in the ROADMAP Phase 2 "Plans" note and in `02-VALIDATION.md`). This plan merges into local `main` and pushes `main`, so it runs only on the main working tree with `main` checked out (sequential dispatch; it is the only plan in wave 4). At plan time the key is unset and defaults to true, which dispatches each plan into an agent worktree, and the orchestrator has no per-plan switch that this plan can set, so every task begins with the main-tree check: `git rev-parse --abbrev-ref HEAD` prints `main`, and `git rev-parse --path-format=absolute --git-dir` equals `git rev-parse --path-format=absolute --git-common-dir` (they differ in a linked or agent worktree). If the check fails, the task merges nothing, pushes nothing, commits nothing and returns `## CHECKPOINT REACHED` with this remedy, word for word: "This plan was dispatched into an agent worktree or onto a branch other than `main`. Set `workflow.use_worktrees` to `false` (`node "$HOME/.claude/gsd-core/bin/gsd-tools.cjs" query config-set workflow.use_worktrees false`, or set `"use_worktrees": false` under `"workflow"` in `.planning/config.json` by hand) and dispatch plan 02-06 again on the main working tree with `main` checked out. Spawning another continuation agent without changing the setting repeats this stop." The executor does not change the setting itself. The continuation agent after each owner stop is a fresh agent; this plan holds no uncommitted work across a stop, and each continuation repeats the main-tree check.

== SSH path ==

ssh -F /Users/neilskinner/.lima/harvey/ssh.config lima-harvey
  (lima writes this Host block: User neilskinner, Hostname 127.0.0.1,
  Port 51721, BatchMode yes. Its IdentityFile lines name lima's own
  generated user key and the owner's ~/.ssh/id_ed25519; no key material is
  reproduced here.)

Every nix remote-store command ran with:
  NIX_SSHOPTS="-F /Users/neilskinner/.lima/harvey/ssh.config -oControlPath=none"

Why -oControlPath=none: lima's ssh.config sets `ControlMaster auto` and
`ControlPath ~/.lima/harvey/ssh.sock`. Nix's ssh-ng store probes
`ssh -O check lima-harvey` without its own -S first, so the probe finds
lima's master socket and reports a master; nix then skips consuming the
`-oLocalCommand=echo started` readiness line it relies on and the daemon
handshake dies with:

  error: cannot open connection to remote store 'ssh-ng://lima-harvey':
    error: protocol mismatch, got 'started
              oixd

With ControlPath=none the probe fails, nix starts its own master on its own
temporary socket, and the store works:

$ nix store info --store ssh-ng://lima-harvey
Store URL: ssh-ng://lima-harvey
Version: 2.35.3
Trusted: 1

Both facts are the Ubuntu 24.04 AppArmor restriction on unprivileged user
namespaces (kernel.apparmor_restrict_unprivileged_userns=1). A nested
`unshare -Ur` cannot write its uid_map: outside the sandbox the process has
no CAP_SETUID over its own userns; inside the nix sandbox it is additionally
uid 1000 in a userns it does not own. A16 is therefore live on this venue.

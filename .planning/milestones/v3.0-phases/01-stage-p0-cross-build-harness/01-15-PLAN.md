# Plan 01-15: The amd64 reference bake and the marker, chain and substrate images

<objective>
This plan puts the first x86_64 images under r9's assembler (D-16) and verifies them the way D-29 settled: member lists against the reference bake. Byte differentials are not used, because assumption A12 was refuted. The reference is a nix derivation that runs Harvey's own `mkimage.sh` once on a writable copy of the flake-built tree. A fresh derivation is always a first bake, so the pass-1 bake-2 failure (`hsecstored missing`) cannot occur. A shim in place of mkpaqfs records each contract's exact input. The first images are the ones the existing boot-test profiles need (research F1 ordering): marker (q35exec, q35churn), chain (q35shell, q35churnshell; it also holds `ps`, the D-27 swap target) and substrate (q35auth). Plan 01-16 adds cpu and auth, and plan 01-19 adds the rest. The reference lists for all nine images come from this one bake.

The five profile configs are not edited here. Plan 01-29 points them at these images (`image:<name>`) after this plan and plan 01-16 land, so the profile move is one reviewable change that ends with no x86_64 profile reading a Harvey-baked image.

Purpose: a verified contents contract for the first three r9-assembled x86_64 images.
Output: `nix/harvey/reference.nix` and three manifests that match the reference.
</objective>

  <action>
`nix/harvey/reference.nix` defines `harvey-reference-amd64` (Linux systems), a plain stdenv derivation. No Plan 9 venue is needed: mkimage is a host shell bake.

- Copy the amd64 tree into a writable `$TMPDIR/harvey`.
- Install a shim at `$TMPDIR/harvey/.build/bin/mkpaqfs`. Before it runs the real Linux `harvey-mkpaqfs`, it records the input directory as a member list in the plan 01-11 format (`f <path> <size> <sha256> <mode>` / `d <path>`) into `$out/<image>.members`. The image name comes from the `-o` basename: `bootfs.paq` -> marker, `bootfs-<x>.paq` -> `<x>`; name the churn variant as mkimage does.
- Paths that carry bake-time p9sk1 material (keys, nvram, domain manifest, the ndb auth files and any file that embeds the authdom token) get `opaque` in place of the sha256. Determine the exact set from mkimage.sh sections 14 and 15 and list it in the nix file.
- Run `HARVEY=$TMPDIR/harvey KERNDATE=${toString harvey.lastModified} sh build/x86_64/mkimage.sh`, with stdenv.cc and the coreutils/grep/sed/awk/tar/findutils mkimage needs.
- If mkimage needs a source file the tree lacks, add it to tree-amd64.nix's install list (with its read site) rather than reading the flake input here.
- mkimage's services section (11d) builds programs with Harvey's host toolchain during the bake. Put `harvey-hostbin` on the derivation's PATH. If that step needs the Plan 9 namespace, run the bake through `mkTreeDerivation`'s proot venue in place of a plain stdenv build, and record which.
- Copy the bake log to `$out/mkimage.log` minus any line containing `password`. Fail the build if any `auth-creds` file is under `$out`, or if the generated password value occurs in any output file.
- Require nine member lists; fail with a named count otherwise.

flake.nix: package `harvey-reference-amd64` (Linux), and the lazy, guarded devshell export `R9_HARVEY_REFERENCE_AMD64`.
  </action>

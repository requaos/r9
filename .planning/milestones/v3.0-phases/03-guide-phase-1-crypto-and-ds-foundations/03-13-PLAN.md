## Rules that bind this plan

- Commit messages carry no AI attribution line of any kind. Nothing is pushed.
- Only `ds/src/tpht/flattened.rs` and this plan's ledger are edited.
- `ds/src/tpht/` is the only place `unsafe` may appear, test code included (D-09). One `// SAFETY:` comment per block, directly above it.
- Tests are in-file `#[cfg(test)] mod tests`; randomized tests use a seeded PRNG with literal seeds.
- Miri sizing is the rule of plan 03-06: every test takes its sizes through `tpht::miri_scaled(native, under_miri)`; none is gated out with `cfg(not(miri))` or `#[ignore]`. Miri-side size here: the `deref_tiny` model test runs 200 operations on 16 blocks (1,024 blocks natively).
- Miri latency is the rule of plan 03-06: after GREEN, time one warm `nix develop -c cargo xtask miri` run and record `MIRI-TIME deref-tiny <seconds>` (whole seconds, digits only). Budget 120 seconds (03-VALIDATION.md). Over budget: record `MIRI-OVER deref-tiny <seconds>` instead and lower Miri-side sizes only, at most twice (first to half, then to the floors of 4 blocks and 50 operations), timing after each; still over at the floors: stop and report the times to the orchestrator.
- Pin ledger format as in plan 03-01, in `P/evidence/PINS-03-13.md`, where `P` is `.planning/phases/03-guide-phase-1-crypto-and-ds-foundations`. The pin id is `deref-tiny`.
- Forward note: plan 03-08 changes `insert` to report whether an entry went home or to a bank. It re-pins the three tests of this plan on a home-only shard, by name, and leaves their assertions as written here.

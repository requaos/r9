GREEN, with these rules:
- A bank is an arena of exactly `BANK_NODES` nodes with indices 0..=254, so an index fits one byte and `0xFF` is never an index. A node holds a state byte, the 16-bit fingerprint, the full 64-bit key, the value words and a link to the next node of its chain. A link names a node by which of the block's two candidate banks it is in plus its one-byte index, with a distinct end marker.
- Candidate banks: `bank0 = mix32(block as u32) % num_banks`, `bank1 = mix32(block as u32 ^ 0x9E37_79B9) % num_banks`; when they are equal and there is more than one bank, `bank1 = (bank0 + 1) % num_banks`. A new node goes to the candidate with more free nodes (a per-bank atomic counter), ties to `bank0`; when the chosen bank has no free node, try the other; when both are full, return `Err(BanksFull)`.
- Claim and publication: claim a free node by a compare-exchange of its state byte from free to `WRITING`; a failed exchange means another claimer took it, so try the next free node. Store the fingerprint, key and value words; then store the state byte to its published value with `Release`; only then link the node at the block's chain head. A reader that reaches a node whose state is `WRITING` or free treats it as absent.
- Chain heads: a boxed slice of atomics, one per home block, owned by this structure (the header has no spare byte; RESEARCH Open Question 6).
- Lookup: walk the block's chain; on a fingerprint match compare the full key; return the value words only when the key matches.
- Serialisation contract, written in the type's doc comment: claims of nodes in a shared bank by different blocks are concurrent and are what the `WRITING` protocol covers; mutations of one block's chain (insert, remove) must be serialised by the caller, which in the flattened shard is that block's seqlock, and a reader that needs a consistent view across a concurrent remove validates against that seqlock generation. Standalone, concurrent readers of a chain with one inserting writer are safe.
- `remove` unlinks the node, sets its state byte to free with `Release` after the unlink, and returns it to the bank's free count.
- Do not copy listing 9.4: no write through a pointer cast from `&T`, and no 7-bit pointer packing.

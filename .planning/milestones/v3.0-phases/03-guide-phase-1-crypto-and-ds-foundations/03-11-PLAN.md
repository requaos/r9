# Plan 03-11: The single end-of-phase owner stop — sandboxed kernel builds on Linux, then `main`

<objective>
Everything that needs the owner's Linux host happens at one stop, in the order of `03-OWNER-STOP.md`: the owner approves the branch push, builds the two sandboxed kernel derivations at the tip and at the base, compares the bytes, builds and rebuilds the fixed-output ISO, runs the suite on the x86_64 host, and reports back. The executor records the verdicts from the return, and `main` is pushed only after a second approval.

Purpose: the one check the Mac cannot make (RESEARCH A8), and the push rules of the standing owner rules.
Output: the pushed branch, `RESULTS.md`, and, after approval, a pushed `main`.
</objective>

## Rules that bind every task in this plan

- Commit messages carry no AI attribution line of any kind.
- Every push needs the owner's explicit approval for that push. The executor checks what is unpushed first and pushes only what was approved.
- The Mac cannot build the sandboxed kernel derivations and cannot reach the owner's host. No verdict for those steps is produced here.
- Between the branch push and the return, make no commit on the Mac, so `main` can take the branch by fast-forward.
- This plan runs on the main working tree with `main` checked out (`workflow.use_worktrees` is `false` in `.planning/config.json`). Each task first checks that `git rev-parse --abbrev-ref HEAD` prints `main` and that `git rev-parse --path-format=absolute --git-dir` equals `git rev-parse --path-format=absolute --git-common-dir`; if not, it pushes nothing, commits nothing and returns `## CHECKPOINT REACHED` saying the plan must be dispatched on the main working tree.

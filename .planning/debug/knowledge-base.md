## aarch64-smp2-hvf-corruption — HVF -smp 2 fork/exec sweep hung because two CPUs shared one kernel stack (and the secondary's sched loop ran IRQ-unmasked)
- **Date:** 2026-11-26
- **Error patterns:** HVF-only, -smp 2, serial wire stops mid-line (`paqfs...s`), torn output interleaved with kernel prints, both CPUs spinning in an MCS lock wait loop, mid page-in sweep stall, qemu `hvf.c:2447 assert(isv)` ISV=0 MMIO write, `cur_frame` inside another CPU's kstack, TCG green while HVF flakes
- **Root cause(s):** `reschedule()` published a preempted proc Ready + enqueued while the preempting CPU still ran on that proc's 16 KiB kernel stack (the `sched: switch` console print stretched the window on HVF, where each UART byte is an MMIO exit); a sibling CPU stole the pid and took traps on the same kstack — overlapping kernel frames corrupted the console MCS queue's stack-resident `LockNode`s, so both CPUs then waited forever for CONS. `block()` had the same publish-before-swtch shape (a wake could ready a proc whose context was not yet saved). Independently, `secondary_main` unmasked IRQs before entering the sched loop, so an IRQ in the `pick_next`→`trap_return` handoff overwrote `PerCpu.cur_frame` with an EL1h frame from the scheduler stack and the tail restored that, leaving `SP_EL1` in a kstack the CPU did not own.
- **Fix:** explicit kernel-stack ownership: `Proc::on_cpu` (set by pick_next/activate_first, cleared only by the owning CPU's sched-loop `release_left_proc`); `reschedule()` now only parks via `swtch` (`blocked_in_kernel`) and `release_left_proc` publishes a preempted proc Ready + enqueues it after the CPU is off its stack (owner-scoped by consuming `PerCpu.current_proc` in the same `PROC_TABLE` critical section); `pick_next` refuses an `on_cpu` proc and carries a debug tripwire; `sched_loop` masks IRQs on entry, `secondary_main` no longer unmasks before it, and `dispatch_irq` EOIs before `preempt` (which now parks).
- **Files changed:** aarch64/src/proc.rs, aarch64/src/smp.rs, aarch64/src/trap.rs, aarch64/src/main.rs, aarch64/src/platform/virt/timer.rs, port/src/sched.rs, UNSAFE-AUDIT.md
- **Why not caught:** no gate existed for this class — TCG (the declared truth venue for the I-cache/aliasing class) does not model real MMIO-exit timing or arbitrary IRQ delivery points, so the publish window was effectively atomic there; the lock-rank/watchdog machinery models lock order and stuck waits, not kernel-stack ownership; and the "sched loop is IRQ-masked" contract had no assertion, so `secondary_main`'s early `unmask_irq` was invisible.
- **Recurrence guard:** `Proc::on_cpu` is enforced structurally in `pick_next` (an owned stack is never started on another CPU), and `pick_next`'s debug-build tripwire panics by name when another CPU's `cur_kstack` still names the candidate (`sched: pid N picked while cpu C still names its kernel stack … — two cpus on one kstack`) — it fired on a real publish violation during development and is silent after the fix; `port::sched::tests::runqueues_any_enqueued_tracks_queued_work` covers the reschedule fast-path probe; the HVF gicv3 -smp 2 smoke gate is the end-to-end witness (8/8 post-fix vs 6/13 pre-fix).

## aarch64-net-smoke-regression — net-smoke panicked at the first ether bind because netif allocated inside the NetIrq-ranked INGRESS lock
- **Date:** 2026-11-26
- **Error patterns:** `panicked at ` truncated to 12 chars, `LOCK RANK VIOLATION`, `holds "netif_ingress" (rank 90); requested "heap_alloc" (rank 80)`, deterministic TCG + HVF at both `-smp 1` and `-smp 2`, panic after `fault: bss page-in va=0x48000` during `rc /lib/netip-static.rc`, net-smoke regression while boot smoke passes, `R9_ACCEL=tcg nix run .#boot-r9-net-smoke` fails at the ether bind
- **Root cause(s):** `port/src/netif.rs` performed heap operations under the NetIrq-ranked `INGRESS` lock (rank 90 > `HeapAlloc` 80): `conv_alloc` built `FrameStore` (a 64 KiB `Vec` plus its free stack) with the guard live, `conv_close` rebuilt the free stack with a freshly collected `Vec` (alloc + dealloc), and `FrameStore::push` grew a zero-capacity `VecDeque` from the rx IRQ retire. The violation was latent until `66a3548` added `smp::register_port_smp()` to `main9`, which activated the ranked-lock checker (`cdd4e61` only defines it; before registration every rank check is a no-op). Contributing condition: the gate's `expect_before` matches `panic` on the first chunk and kills qemu mid-drain, so the full message never reached the capture and two prior attempts chased the console instead.
- **Fix:** c42a66f — allocate `FrameStore` before taking INGRESS (NETIF, the unranked lifecycle lock, is held throughout so the slot and its store's presence are stable), reset the free stack in place with `clear()` + `extend()`, and preallocate the queue to `FRAME_SLOTS` (`VecDeque::with_capacity`) so `push` never grows; `push` now `debug_assert!`s `len < capacity` as the no-alloc contract.
- **Files changed:** port/src/netif.rs, .planning/phases/05-guide-phase-3-early-smp-course-correction-and-memory-pools/deferred-items.md
- **Why not caught:** no gate existed for the class until 66a3548 activated the rank checker — the violating code shipped in the 05-08 netif locking conversion and passed every gate while the checker was dormant. Host `cargo test` cannot catch it either: tests use the system allocator, so no `heap_alloc` lock is requested and the rank stack never sees the inversion; only a kernel boot reaches `GlobalQuickAlloc`.
- **Recurrence guard:** the ranked-lock checker itself is the guard now that `register_port_smp()` runs at boot — any alloc/dealloc under `NetIrq`/`Console` panics by name at the heap lock (`rank_before_acquire` names both locks). The fix adds the local no-alloc contract: `FrameStore`'s containers are capacity-pinned and `push`'s `debug_assert!(len < capacity, "FrameStore::push would allocate under INGRESS")` fires before a growth would. Recurring class to check first on any future `LOCK RANK VIOLATION`: **never allocate (or free) inside a ranked lock — rank checkers only run once the arch registers with `port::smp`, so a latent violation can surface only when the checker is activated**; when a net-smoke panic text is truncated, drive qemu with a raw pty serial (or set a breakpoint on `rust_begin_unwind` via the gdbstub) instead of trusting the gate capture.

## aarch64-palloc-evictor — mem-pressure evictor reclaimed nothing under two-CPU exhaustion (single-frame reclaim lost to the peer; unmapped-blind FIFO livelocked hot text)
- **Date:** 2026-11-27
- **Error patterns:** `fault: phys page alloc failed`, `user fault: unresolvable … name=hseq` / `name=hsort`, `evictor: dropped_text=0 dropped_data=0 pinned_skipped=0`, pressure gate red at 2048/1536/1200 frames, `fault: text page-in va=0x18000` repeated hundreds of thousands of times, evict→refault wedge, `WATCHDOG`-less `wedgedbg: pipe-RPC wedge shape`, cap 512 `DataAbortSameEl far=0x20118`, cap 1024 wedge
- **Root cause(s):** three contributing defects, all required: (1) `PageAlloc::alloc_clean` asked the arch evictor for ONE frame per `MAX_EVICT_ATTEMPTS` attempt; the freed frame returns to the shared `dirty` pool and the sibling CPU consumed it before the caller's retry (measured `freed … dirty=1 active=2047`, next attempt `dirty=0 active=2048`), so a caller starved itself to `OutOfSpace` while reclaimable cached pages remained, and the fault path killed it; (2) `PageCache::select_eviction_victim` was a mappedness-blind FIFO — once cold pages were gone it evicted hot text mapped by running procs, which re-faulted immediately (377,377 refaults of one VA), an evict/refault livelock; (3) the gate's authored load never exhausted the pool (exec churn) or demanded ~100x it (`hseq 1 400000`), and `pinned_skipped > 0` was structurally unreachable from this image's userland (write buffers are promoted off the droppable queue; `pwrite`'s read-only source is an uncached stack/.bss page). Corollary: `#c/sysstat` reported 0/0/0 both when the evictor never ran and when it ran and failed, so the counters could not localize the defect without pool/cache diagnostics.
- **Fix:** 667170b — `EVICT_BATCH_FRAMES=16` (the evictor reclaims a batch so the caller keeps a margin against a thieving peer); `select_eviction_victim` prefers rmap-empty (unmapped/cold) pages — no PTE walk, no shootdown, no refault — and falls back to the oldest mapped page; `#c/sysstat` gained `palloc.hash:`/`palloc.pool:` and `evict_calls`/`reclaimed`/`free_failures`; the aarch64 gate drives one bounded `hseq 1 44000 | hsort > /dev/null` burst (`R9_PRESSURE_LINES`) sized to exceed dirty+clean but stay inside the cold cache, asserts `dropped_text>0, dropped_data>0, evict_calls>0, reclaimed>0, free_failures==0`, and forbids `phys page alloc failed`; `pinned_skipped` is reported, not asserted (pinning proven by `pagecache::pinned_cached_page_is_skipped_until_unpinned`); the background pinned-reader stage was removed; the x86_64 driver drops the same unreachable assertion.
- **Files changed:** port/src/palloc.rs, port/src/pagecache.rs, port/src/devcons.rs, aarch64/src/pagealloc.rs, aarch64/src/fault.rs, aarch64/src/main.rs, x86_64/src/pagealloc.rs, x86_64/src/proc.rs, x86_64/src/main.rs, gates/aarch64/mem-pressure.expect, gates/x86_64/mem-pressure.expect, nix/gates/mem-pressure-r9.sh, nix/gates/mem-pressure-r9-x64.sh
- **Why not caught:** no gate existed that *genuinely* exhausted the pool with a bounded, self-limiting workload — the exec-churn loop never emptied dirty+clean, so the evictor was never called, and the only known repro (`hseq 1 400000`) demanded ~100x the pool, which no reclaim policy can survive; the host tests exercised `PageAlloc` and `PageCache` independently, never the live allocator↔evictor seam under a second CPU, where the freed frame is stolen and a pure FIFO meets hot mapped text; and the gate planted a criterion (`pinned_skipped > 0`) that the architecture cannot produce, so it could never be green even after the evictor was fixed.
- **Recurrence guard:** `port/src/palloc.rs::alloc_clean_requests_the_reclaim_batch` pins the API contract (the evictor is asked for `EVICT_BATCH_FRAMES`, not one frame); `port/src/pagecache.rs::unmapped_pages_are_evicted_before_mapped_ones` pins cold-first victim order; `port/src/pagecache.rs::pinned_cached_page_is_skipped_until_unpinned` pins the real `PageAlloc::pin_frame` seam; the live `boot-r9-mem-pressure` gate now asserts `dropped_text/dropped_data/evict_calls/reclaimed > 0` with `free_failures == 0` and forbids `phys page alloc failed`, and `#c/sysstat` exposes the cache/pool gauges so a starvation or thrash regression is visible in the capture. **Class rule: a reclaim path that returns frames to a shared pool must reclaim a batch (or reserve), never one frame per attempt, whenever a peer can allocate concurrently; and an eviction policy must prefer unmapped/cold victims — a mappedness-blind FIFO livelocks hot text under sustained pressure. A gate criterion must assert something the workload can actually produce; if the architecture cannot reach it, prove the contract with a host test and delete the assertion.**

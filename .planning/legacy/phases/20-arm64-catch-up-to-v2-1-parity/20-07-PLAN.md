<objective>
Measure the two unknowns that group B rests on, before porting anything: whether a ramfs writable venue works on arm64 tier-1 and exactly where it fails today, and whether the lone-member brk defect exists on aarch64.

Purpose: D-09. Research inventoried these items without measuring them; PATTERNS notes the brk item may not be a defect on aarch64 because aarch64 demand-faults Bss pages.
Output: two probe fixtures committed, measurements recorded, an owner decision.

Stated assumptions under test:
- A-venue: `ramfs` builds with `objtype=arm64` by the per-target install rule, mounts on the current kernel (sys/src/cmd/ramfs.c line 236 forks with `RFFDG|RFPROC|RFNAMEG|RFNOTEG`, an RFPROC call the kernel already serves, and mounts its own pipe at line 245), and the write flow over it fails only at the two arms research lists for mounts (`devmnt: the mounted tree is read-only this era`, `create: directories unsupported this era`) plus the union create.
- A-rfork: the third arm research lists, `rfork: bad flags for non-RFPROC` (r9 `aarch64/src/syscall.rs` line 1628), sits on the non-RFPROC path only. `/bin/ramfs` never reaches it. Its real callers are lib9p servers (`postmountsrv`, sys/src/lib9p/post.c line 45, a bare `rfork(RFFDG)` whose return value is not checked), and no lib9p server is in the arm64 image. So the reject is measured by a dedicated probe, `rfdprobe`, which checks the return value. Route chosen: the probe, not baking sys/src/lib9p/ramfs.c, because post.c ignores the failure and would give no clean red step.
- A-brk: aarch64's lazy end move plus the demand pager already serves a lone member's brk growth, so the x86_64 eager-map fix is not needed.

Specless-probe note: step 7.95 was skipped visibly (no SPEC, no requirement IDs at planning time).
</objective>

It pins the non-RFPROC fd-group split (b4) in two phases. Phase `rffdg`: the parent opens `/dev/null` (falling back to `dup` of fd 1) and keeps the fd; it calls `rfork(RFPROC)` with no fd flag, so the child shares the parent's fd table; the child calls bare `rfork(RFFDG)` and checks the return value, and on -1 it `exits` with the string `rffdg: ` followed by the errstr; otherwise it closes the kept fd in its now-private table and `exits(nil)`. The parent waits, treats a non-empty exit string as the failure reason, and then checks with `dirfstat` that its own copy of the fd is still open (reason `parent fd closed by child` when it is not: the split did not happen). Phase `rfcfdg`: a second `rfork(RFPROC)` child calls bare `rfork(RFCFDG)`, on -1 `exits` with `rfcfdg: ` and the errstr, otherwise checks with `dirfstat` that the kept fd number is no longer open in itself (`exits("rfcfdg: fd still open")` when it is) and `exits(nil)`; the parent waits and again checks its own fd is still open. A child reports only through its exit string, never by printing, because after `RFCFDG` it has no fd 1 or 2. The parent prints `rfdprobe: ok` with a nil status when both phases pass, otherwise `rfdprobe: FAIL <rffdg|rfcfdg> <reason>` for the first failing phase and `exits` with that text.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user proc to kernel syscall arms | rfork flags, create paths and perm words, write buffers arrive from ring 3 |
| kernel devmnt to a user-space 9P server | Writes and creates now cross to the mounted server |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-18 | Tampering | Unvalidated user pointers in the create and write arms | high | mitigate | Only `UserSlice` / `UserString` / `copy_user_str` paths, as in the x86_64 originals; no raw pointer reads are added |
| T-20-19 | Elevation | A `#`-rooted create crossing a mount it should not | medium | mitigate | The `nomount` bit is computed from the path's first byte and passed to both union twins, as x86_64 does |
| T-20-20 | Denial of service | An fd reference leaked on an early return in a device arm | medium | mitigate | `fd_op_done` on every path; the boot-test profiles and the sweep exercise open/close churn |
| T-20-21 | Tampering | fd-group split sharing state with the old group | medium | mitigate | `deep_copy()` under the group lock into a new `Arc<Lock<..>>`; RFCFDG takes the shared empty singleton as x86_64 does |
| T-20-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is added |
</threat_model>

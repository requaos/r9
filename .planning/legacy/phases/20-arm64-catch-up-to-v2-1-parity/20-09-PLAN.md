<objective>
Port the churn leak gate to aarch64 and use it first as a measuring instrument: run it against the unfixed exit path and record whether the exit leak exists on arm64.

Purpose: D-08 puts the churn gate with the syscall-path work because it is the only positive pin for the exit-leak fix. Building it before 20-10 makes the fix a red-to-green proof if the leak exists, and tells us honestly if it does not.
Output: local r9 commits (kernel driver + profile; xtask), one local Harvey commit (fixtures), the pre-fix slope on record.

Stated assumption under test (research A5, marked ASSUMED there): aarch64 leaks about 16 KiB of kernel heap per exec/exit, as x86_64 did before 17-02. Consequences: if the pre-fix slope fails the gate, 20-10's exit ports must turn it green. If the pre-fix slope already passes, the leak does not exist on aarch64 in that form; 20-10 still ports the exit drains for donor correctness (D-03 names the exit half), and this gate stands as a regression pin rather than a red-to-green proof. Neither branch changes this plan's design, so there is no checkpoint here; the result is reported in the summary and at the 20-11 checkpoint.

Specless-probe note: step 7.95 was skipped visibly (no SPEC, no requirement IDs at planning time).
</objective>
